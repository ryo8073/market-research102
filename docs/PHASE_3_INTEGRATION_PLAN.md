# Phase 3: Deeply Connected Investment Analysis

## ビジョン

各タブ・データソースが孤立せず、**投資判断に直結する統合的な洞察**を提供する。
ユーザーは1つの物件・地域を見るたびに、複数の視点が**自動的に紐づいた**判断材料を得る。

## 統合の3層構造

```
┌─────────────────────────────────────────────────────────┐
│  Layer 3: Investment Decision Hub (新タブ⑭)              │
│  「総合判断」: 経済+空間+商圏+物件タイプ レコメンド統合   │
└──────────────────┬──────────────────────────────────────┘
                   │
       ┌───────────┼───────────────┬───────────────┐
       │           │               │               │
       ▼           ▼               ▼               ▼
   Layer 2:  各タブが「他タブの主要指標」を冒頭サマリで参照
   ─────────────────────────────────────────────────
   LQ → EBM → シフトシェア → ギャップ → 不動産 → 商圏 → 地図
   ↑                                                  ↓
   └──────── 分類粒度トグル（major/mid/extended）共通化 ─┘

       ▼           ▼               ▼               ▼
   Layer 1:  事前計算データ（prefectures + municipalities）
   ─────────────────────────────────────────────────
   - 大分類17 + 中分類95 + 農林業補完
   - 多角化指標(HHI/Shannon/N_eff)
   - 通勤歪み(inflow/outflow)
   - NLNI(地価/洪水/用途/DID/医療/商業/立地適正)
   - OSRM(車5分/10分圏)
   - 人口推計(2020-2070)
```

## 実装順序（このセッション）

### Step 1: 中分類シフトシェアの事前計算
**Why**: 中分類でEBM・基盤雇用は見えるが、競争力分析(RS)は大分類のみ。
**実装**: precompute_json.py に中分類シフトシェアを追加。

### Step 2: 詳細タブ(①②③)の分類粒度トグル対応
**Why**: スコアカードで「中分類」を選んでも、LQタブ・EBMタブが大分類のままで一貫性がない。
**実装**: granularity を URL クエリパラメータ + Context で共有。

### Step 3: Investment Decision Hub (新タブ⑭)
**Why**: お客様への説明で「結局この物件は買うべきか？」に答える統合タブが必要。
**実装**:
- 物件タイプ別の評価マトリクス（住居/商業/オフィス/物流の4軸）
- 各物件タイプに対し「経済根拠」「立地根拠」「リスク要因」「商圏根拠」を統合
- 全タブから引いた数値をクロス参照

### Step 4: NLNI×経済 3軸クロス散布図
**Why**: 「商業地域で地価高めだが商業漏損もある→出店適地」のような複合判断ができない。
**実装**: /compare ページに散布図追加（X=基盤率, Y=地価, サイズ=人口, 色=洪水）

### Step 5: 立地適正化「居住誘導 vs 都市機能誘導」区別
**Why**: 投資物件タイプで追い風の区域が異なる。
**実装**: NLNI A35 データを区別取得（データ取得スクリプト追加）

## 成功基準

- ✅ 1物件選んだら、その物件タイプに最適な判断材料が **5秒以内に集約表示** される
- ✅ 各タブで「なぜこの判断が正しいか」の**他タブ根拠**が見える
- ✅ お客様への説明テンプレが**自動生成**される
