## 🔴 優先度: 高（既知の問題・機能リスク）

### B1. 商圏分析の haversine 距離判定の限界
**場所**: `ci102-nextjs/src/lib/use-muni-centroids.ts:findMunicipalitiesInRadius`

**問題**:
- 直線距離(haversine)で判定。地形・道路網を考慮しない。
- 大面積市町村（北海道郡部、紀伊半島の山岳村等）は**セントロイドのみで判定**するため、境界の一部だけ圏内でも全体が集計対象。
- 海岸線・離島では実走行距離との乖離が著しい。

**対応案**:
- Phase 2 E (OSRM 全国拡大) 完了後に走行時間ベースに切替
- 面積補正係数の追加（市町村面積で重み付け）
- 「圏内市区町村数」だけでなく「圏内ポリゴン面積率」も表示

### B2. 国土地理院ジオコーディング API のレスポンスばらつき
**場所**: `ci102-nextjs/src/app/api/geocode/route.ts`

**問題**:
- 「新宿区西新宿2-8-1」だけだとヒットしないことがある（都道府県名必須）
- 番地レベルでの精度は街区まで（地番ピンポイントは取れない）
- 完全一致しない場合は近隣候補が返るが、ユーザーが判別できない

**対応案**:
- 入力ヒントを強化（「東京都新宿区西新宿2-8-1」のように都道府県名から）
- 候補が複数返った時の選択UI改善（住所の階層を明示）
- 失敗時にGoogle Mapsへのフォールバックリンク提示

### B3. 中分類版データの市区町村レベル農林業統合
**場所**: `scripts/precompute_json.py:compute_municipalities`

**問題**:
- 県全体の中分類+農林業データは正確だが、市区町村レベルでは農林業センサスの按分推計値を使用
- 農業従事者が極小（雇用<5,000の市町村）では基盤雇用比率が極端に振れる可能性

**対応案**:
- 市区町村レベルでの解釈ガイドに「按分推計のため小規模自治体では参考値」と注記済
- 統計テストで小規模自治体の異常値を検出する関数を追加

**場所**: `custom-metro-tab.tsx`

**問題**:

### U3. 商圏分析でNLNI 情報が表示されない
**場所**: `trade-area-tab.tsx`

**問題**:

**対応案**:
- TradeAreaMap で NLNI レイヤーを重ね合わせ可能に

### U4. compareページに新機能が反映されていない
**場所**: `app/compare/page.tsx`

**問題**:

**対応案**:
- /compare に「比較対象タイプ」セレクター追加（都道府県 / 都市圏 / カスタム）

### U5. 通勤歪み警告の繰り返し表示
**場所**: スコアカード上部 + insights セクション

**問題**:
